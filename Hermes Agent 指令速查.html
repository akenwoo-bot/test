01

進入 WSL 環境

Hermes 通常安裝在 WSL 的 HermesAgent 發行版中。在開始任何操作前， 需從 Windows 端進入 WSL 並確認環境正常。

進入 WSL HermesAgent 發行版
從 Windows PowerShell 或 CMD 執行，切換至 WSL 中名為 HermesAgent 的 Linux 發行版。 若尚未安裝該發行版，請先在 wsl --list --online 中搜尋並安裝。
wsl -d HermesAgent
確認使用者與系統資訊
進入 WSL 後，執行以下三條命令確認目前使用者、工作目錄與核心版本，確保環境無異常。
# 查看目前使用者 whoami # 查看目前工作目錄 pwd # 查看系統核心與架構資訊 uname -a
確認 Hermes 指令是否存在
使用 command -v 檢查 hermes 是否在 PATH 中； 再用 --version 確認已安裝的版本號碼。
command -v hermes hermes --version
02

啟動與基本使用

以下為 Hermes 最核心的啟動方式，涵蓋互動式聊天、單次問答、Session 續接、 預載 Skills 與隔離 worktree 等場景。

啟動互動式聊天
最基礎的啟動方式。進入後可與 Agent 進行多輪對話，輸入 exit 或 Ctrl+D 結束。
hermes
單次問答模式
使用 -q 旗標後接引號包圍的問題，Hermes 會執行一次推理後立即輸出結果並退出， 適合腳本整合或快速測試。
hermes chat -q "你好，請確認目前模型設定"
繼續上一個 Session
使用 -c（continue）自動載入最近一次 Session 的對話歷史，讓 Agent 保有上下文。 適合中斷後繼續同一工作情境。
hermes -c
指定回復某個 Session
透過 --resume SESSION_ID 可精確載入指定 Session。 可用 hermes sessions list 查詢 ID。
hermes --resume SESSION_ID
啟動時預載 Skills
使用 -s 以逗號分隔的方式預載多個 Skill 模組， Agent 會在該 Session 中自動套用這些專長流程。
hermes -s codebase-inspection,systematic-debugging,test-driven-development
Git worktree 隔離執行
-w 讓 Hermes 在 Git 專案中建立隔離的 worktree， 避免 Agent 操作影響主分支，適合實驗性修改或並行開發。
hermes -w
略過危險命令確認（YOLO 模式）
--yolo 會略過所有危險操作（如刪除檔案、執行 shell 命令）的確認提示。 僅建議在完全信任的隔離環境中使用，否則可能造成資料遺失。
hermes --yolo
⚠️ 此模式會自動執行所有指令而不詢問，請務必在沙箱或備份完成後使用。
03

查看狀態與診斷

查看 Hermes 狀態
顯示目前安裝狀態、模型設定、活躍 Gateway、Session 數量等摘要資訊， 適合快速確認整體健康狀態。
hermes status
執行環境診斷
doctor 會自動檢查 API Key 有效性、模型連線、Skills 狀態、 Gateway 行程、設定檔權限等多項項目，並輸出通過／失敗清單。
hermes doctor
輸出除錯摘要
產生一份包含版本、環境、設定、最近錯誤的完整 dump 檔案， 方便貼給技術支援團隊排查問題。
hermes dump
查看版本資訊
以下兩條指令效果相同，都會輸出當前 Hermes 版本號碼。
hermes version hermes --version
04

模型與 Provider 設定

Hermes 支援多種模型 Provider（OpenAI、Google Gemini、Anthropic 等）。 以下指令用於查看、編輯與切換模型設定。

進入互動式模型選擇器
啟動 TUI 介面，可圖形化選擇 Provider 與模型，並即時測試連線。
hermes model
查看目前設定
印出 ~/.hermes/config.yaml 中所有已設定的欄位，包含 model、provider、tools 等。
hermes config show
查看設定檔路徑
輸出 config.yaml 與 .env 的絕對路徑，方便快速定位檔案。
hermes config path hermes config env-path
編輯主設定檔
以系統預設文字編輯器（$EDITOR / $VISUAL）打開 config.yaml，可手動調整任何設定項目。
hermes config edit
設定 Google Gemini Provider
將 model.provider 設為 gemini，之後所有請求將走 Google Generative Language API。
hermes config set model.provider gemini
設定 Gemma 4 31B 模型
在 provider 已設為 gemini 的前提下，將預設模型設為 gemma-4-31b-it。
hermes config set model.default gemma-4-31b-it
設定 Google OpenAI-compatible endpoint
指定 Gemini 的 OpenAI 相容端點，讓 Hermes 可用 OpenAI 格式呼叫 Gemini 模型。
hermes config set model.base_url https://generativelanguage.googleapis.com/v1beta/openai
查看模型設定片段
用 grep 快速印出 config.yaml 中 model: 段落，確認設定是否已正確寫入。
grep -A4 '^model:' ~/.hermes/config.yaml
05

API Key 與環境變數

Hermes 的 API Key 統一存放在 ~/.hermes/.env。 編輯後需重新載入 shell 或重開 Terminal 才會生效。

編輯 .env 檔案
使用 nano（或 $EDITOR）打開環境變數檔案，可加入 / 修改任意 Provider 的 API Key。
nano ~/.hermes/.env
Google AI Studio / Gemini 常用設定
以下三行是最常見的 Gemini 設定。 GEMINI_BASE_URL 指向 OpenAI 相容端點，讓 Hermes 可用統一的 chat/completions 格式呼叫。
GOOGLE_API_KEY=你的_google_api_key GEMINI_API_KEY=你的_google_api_key GEMINI_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai
設定 .env 權限為 600
chmod 600 確保只有檔案擁有者可讀寫，防止其他使用者或服務讀取 API Key。
chmod 600 ~/.hermes/.env
測試 Google 模型清單是否可讀取
先用 set -a + . .env 載入環境變數，再以 curl 呼叫 models 端點，確認 API Key 有效且可列出可用模型。
set -a . ~/.hermes/.env set +a curl -sS -H "x-goog-api-key: ${GOOGLE_API_KEY}" \ https://generativelanguage.googleapis.com/v1beta/models | head
測試 Gemma 4 31B 聊天請求
以 OpenAI chat/completions 格式發送一條最小請求，若回傳 "OK" 即代表模型與 API Key 均正常。
set -a . ~/.hermes/.env set +a curl -sS \ -H "Authorization: Bearer ${GOOGLE_API_KEY}" \ -H "Content-Type: application/json" \ https://generativelanguage.googleapis.com/v1beta/openai/chat/completions \ -d '{"model":"gemma-4-31b-it","messages":[{"role":"user","content":"Reply OK only."}],"max_tokens":8}'
06

Skills 管理指令

Skills 是任務專長模組，讓 Agent 在程式碼檢查、GitHub 工作流、研究論文、PDF、Notion、 Google Workspace、MLOps 等情境中套用更精準的流程。

列出已安裝 Skills
印出目前所有已安裝的 Skill 名稱、版本與狀態。
hermes skills list
互動式開關 Skills
啟動 TUI，可逐一啟用 / 停用每個 Skill，並即時預覽效果。
hermes skills config
搜尋 Skills Hub
在遠端 Skills Hub 中依關鍵字搜尋可用 Skill。以下為四個常見搜尋範例。
hermes skills search github hermes skills search pdf hermes skills search research hermes skills search notion
預覽 Skill 內容
顯示指定 Skill 的描述、包含的工具、預設參數等資訊，安裝前可先 inspect。
hermes skills inspect IDENTIFIER
安裝 / 強制安裝 / 跳過確認
基本安裝會先詢問確認；加 --force 可覆蓋已存在版本； --yes 則完全跳過互動確認，適合腳本自動化。
hermes skills install IDENTIFIER hermes skills install IDENTIFIER --force hermes skills install IDENTIFIER --yes
檢查 / 更新 / 移除 Skills
check 檢查有無新版本；update 批量更新至最新版； uninstall 移除由 hub 安裝的 Skill。
hermes skills check hermes skills update hermes skills uninstall IDENTIFIER
常用 Skills 組合推薦
以下為三種高頻使用情境的 Skill 組合，可搭配 -s 啟動。
# 開發工作 hermes -s codebase-inspection,systematic-debugging,test-driven-development # GitHub 協作 hermes -s github-auth,github-pr-workflow,github-code-review,github-issues # 研究寫作 hermes -s arxiv,research-paper-writing,llm-wiki
07

工具 Toolsets 管理

Tools 控制 Agent 能使用哪些能力，例如終端機、檔案操作、瀏覽器、記憶、TTS、排程、圖片分析等。 不同平台（CLI / Telegram / Discord / WhatsApp）可各自套用不同工具集。

查看工具清單
列出所有可用工具及其目前的啟用 / 停用狀態。
hermes tools list
互動式設定工具
啟動 TUI 逐項開關工具，支援按平台分組設定。
hermes tools
啟用常用工具
一次啟用多個工具，以空格分隔。以下為一般使用與開發情境的兩組推薦。
# 一般使用 hermes tools enable web browser terminal file memory skills todo # 開發常用 hermes tools enable terminal file code_execution browser skills memory session_search
停用暫時不用或敏感工具
停用如 rl（強化學習）、moa（混合 Agent）、 homeassistant（智慧家居）等較具風險或暫不需用的工具。
hermes tools disable rl moa homeassistant
💡 不同平台（CLI、Telegram、Discord、WhatsApp）可各自套用預設工具集或自訂工具， 避免在社群平台暴露敏感操作能力。

Session 管理

列出歷史 Session
印出所有歷史 Session 的 ID、標題、最後更新時間。
hermes sessions list
互動式瀏覽 Session
以 TUI 介面翻閱 Session，可搜尋、預覽摘要後選擇載入。
hermes sessions browse
重新命名 Session
為指定 Session 設定更有意義的標題，方便日後查找。
hermes sessions rename SESSION_ID "新的標題"
匯出 Session
將指定 Session 的完整對話歷史匯出為 JSON / Markdown 檔案。
hermes sessions export SESSION_ID
刪除 / 清理 Session
delete 刪除單一 Session；prune 批量清理舊 Session（可依時間或數量）。
hermes sessions delete SESSION_ID hermes sessions prune

Memory 記憶功能

查看 Memory 設定
顯示記憶系統目前狀態、已記錄條數、記憶檔路徑等資訊。
hermes memory
查看記憶資料夾
記憶資料通常位於 ~/.hermes/memories/。 若尚未產生 MEMORY.md 或 USER.md，代表 Agent 尚未寫入記憶，屬正常狀態。
ls -la ~/.hermes/memories/

Telegram 綁定流程

Hermes 可透過 Gateway 連接 Telegram。建議先用前台模式測試， 確認可用後再安裝背景服務（systemd / user service）。

步驟 1：建立 Telegram Bot

在 Telegram 中找到 @BotFather，輸入 /newbot 建立新 bot。 完成後 BotFather 會回傳一組 token，格式類似：

1234567890:AAxxxxxxxxxxxxxxxxxxxxxxxxxxxx

步驟 2：取得自己的 Telegram User ID

在 Telegram 中找到 @userinfobot，傳任意訊息後它會回覆你的 numeric user ID，例如：

123456789

步驟 3：使用 Hermes 互動式設定

hermes setup gateway

設定時需填入：
• TELEGRAM_BOT_TOKEN：BotFather 給的 token
• TELEGRAM_ALLOWED_USERS：你的 Telegram numeric user ID
• TELEGRAM_HOME_CHANNEL：你的 Telegram numeric user ID

步驟 4：手動設定 .env

nano ~/.hermes/.env
TELEGRAM_BOT_TOKEN=你的_bot_token TELEGRAM_ALLOWED_USERS=你的_telegram_user_id TELEGRAM_HOME_CHANNEL=你的_telegram_user_id
⚠️ TELEGRAM_ALLOWED_USERS 不建議留空， 否則任何找到 bot 的人都有機會使用你的 Hermes 與 API 額度。

步驟 5：前台測試 Gateway

hermes gateway run

接著到 Telegram 對 bot 傳 /start，再測試：「你好，請告訴我目前使用的模型」

前台模式下可即時看到 log 輸出，確認無誤後按 Ctrl+C 結束。

步驟 6：安裝背景服務

# 安裝背景服務（systemd user service） hermes gateway install # 啟動 hermes gateway start # 查看狀態 hermes gateway status # 重啟 hermes gateway restart # 停止 hermes gateway stop # 移除背景服務 hermes gateway uninstall
11

Pairing 使用者授權

Hermes 提供 pairing 機制，用於核准或撤銷使用者的存取權， 適合多使用者共用同一個 Hermes 實例的場景。

查看 pending 與 approved users
列出所有待審批（pending）與已核准（approved）的使用者。
hermes pairing list
核准 pairing code
以使用者提供的 pairing code 完成授權。
hermes pairing approve CODE
撤銷使用者 / 清除 pending
revoke 撤銷已核准使用者的存取； clear-pending 清除所有待審批的 pairing code。
hermes pairing revoke USER_ID hermes pairing clear-pending

Cron 排程任務

Hermes 支援 cron job，可用於定時執行任務、產出報告或透過 Telegram 傳送通知。

查看 cron 指令說明
印出 cron 子命令的完整幫助資訊。
hermes cron --help
查看目前排程
列出所有已設定的排程任務、執行時間與輸出平台。
hermes cron list
💡 建立或管理排程時，可依 CLI 提示輸入任務內容、執行時間（cron expression）與輸出平台（stdout / Telegram / 檔案等）。

MCP 與外部工具整合

MCP（Model Context Protocol）可讓 Hermes 與其他工具或服務互通， 例如資料庫、檔案系統、第三方 API 等。

查看 MCP 指令說明
印出 mcp 子命令幫助。
hermes mcp --help
查看 MCP 伺服器設定
列出目前已配置的 MCP server 清單與連線狀態。
hermes mcp list
執行 Hermes 作為 MCP Server
將 Hermes 本身作為 MCP server 對外提供服務， 讓其他 MCP 相容 client（如 Claude Desktop、Cursor）可呼叫。
hermes mcp serve

Plugins 管理

Plugins 為外掛模組，可擴充 Hermes 的功能，如新增工具、介面、整合等。

查看 / 列出 Plugins
--help 印出幫助；list 列出已安裝 plugin 與版本。
hermes plugins --help hermes plugins list
安裝 / 更新 / 移除 Plugin
以 PLUGIN_IDENTIFIER 指定外掛名稱。 update 升級至最新版，remove 完全移除。
hermes plugins install PLUGIN_IDENTIFIER hermes plugins update PLUGIN_IDENTIFIER hermes plugins remove PLUGIN_IDENTIFIER
15

Logs 與故障排查

查看最近 Logs
印出最近一批 log 紀錄。
hermes logs
即時追蹤 Logs
以 -f（follow）模式即時串流 log 輸出，適合監控 Gateway 或執行中任務。
hermes logs -f
僅查看錯誤 Logs
過濾出 error 等級以上的 log，快速定位問題。
hermes logs errors
查看最近一小時 Logs
使用 --since 限定時間範圍，支援 1h、30m、2d 等格式。
hermes logs --since 1h
Telegram Gateway 沒反應排查步驟
依序執行以下三項，確認 Gateway 狀態、即時 log 與 .env 設定是否正確。
# 1. 確認 gateway 是否正在執行 hermes gateway status # 2. 即時追蹤 log，看有無錯誤 hermes logs -f # 3. 確認 .env 中 Telegram 相關變數 grep -E 'TELEGRAM_BOT_TOKEN|TELEGRAM_ALLOWED_USERS|TELEGRAM_HOME_CHANNEL' ~/.hermes/.env
Gemini API 回 403 常見原因
若 Gemini 回傳 403，常見原因包括： billing 未啟用、project 被拒絕存取、API key 權限限制錯誤、 尚未接受 Gemini API 條款、或使用了不支援的 project。
# 測試生成是否成功 set -a . ~/.hermes/.env set +a curl -sS \ -H "Authorization: Bearer ${GOOGLE_API_KEY}" \ -H "Content-Type: application/json" \ https://generativelanguage.googleapis.com/v1beta/openai/chat/completions \ -d '{"model":"gemma-4-31b-it","messages":[{"role":"user","content":"Reply OK only."}],"max_tokens":8}'

備份與重設

備份 Hermes 設定與資料
將 ~/.hermes 與 ~/.local/bin/hermes 打包為帶時間戳的 tar.gz，方便日後還原。
mkdir -p ~/hermes-backups backup=~/hermes-backups/hermes-backup-$(date +%Y%m%d-%H%M%S).tar.gz tar -czf "$backup" --ignore-failed-read ~/.hermes ~/.local/bin/hermes ls -lh "$backup"
停止 Gateway（重設前）
重設前務必先停止 Gateway，避免執行中服務干擾。以下指令會嘗試多種方式停止，忽略不存在的行程。
hermes gateway stop 2>/dev/null || true systemctl --user disable --now hermes-gateway 2>/dev/null || true pkill -f "hermes.*gateway" 2>/dev/null || true
刪除 Hermes（重設）
刪除執行檔與資料目錄。重設前請務必確認已備份。
rm -f ~/.local/bin/hermes rm -rf ~/.hermes
⚠️ 此操作不可逆，所有設定、Session、Memory 都會被清除。
重新安裝 Hermes
從 GitHub 原始碼下載安裝腳本。 加 --skip-setup 可跳過互動式設定，之後再手動 hermes setup。
# 一般安裝 curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash # 跳過互動式 setup curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash -s -- --skip-setup
重新載入 shell 設定
安裝後需重新載入 .bashrc，讓 hermes 指令在當前 terminal 生效。
source ~/.bashrc
17

更新與解除安裝

更新 Hermes
拉取最新版本並更新執行檔，設定檔與資料會保留。
hermes update
檢查更新後狀態
更新後執行 version 確認版本，再執行 doctor 確認環境正常。
hermes version hermes doctor
解除安裝 Hermes
使用內建 uninstall 可安全移除執行檔與背景服務。 若要手動刪除完整資料，請先備份再執行 rm。
# 內建解除安裝 hermes uninstall # 手動刪除（先備份！） rm -f ~/.local/bin/hermes rm -rf ~/.hermes

建議日常工作流

一般使用者每日啟動
進入 WSL 後直接啟動 Hermes 互動式聊天。
wsl -d HermesAgent hermes
開發工作建議
進入專案目錄後，預載程式碼檢查、除錯、TDD 相關 Skills。
wsl -d HermesAgent cd /path/to/project hermes -s codebase-inspection,systematic-debugging,test-driven-development
GitHub 協作建議
預載 GitHub 認證、PR 工作流、Code Review、Issue 管理 Skills。
hermes -s github-auth,github-pr-workflow,github-code-review,github-issues
研究寫作建議
預載 arXiv 搜尋、研究論文寫作、LLM Wiki 等 Skills。
hermes -s arxiv,research-paper-writing,llm-wiki

總結與 FAQ

核心操作五類
Hermes Agent 的核心操作可分為：模型設定、工具權限、Skills、Gateway、維護診斷。 日常使用只需掌握以下幾組指令即可完成大多數工作：
# 啟動 hermes # 診斷 hermes doctor # 模型設定 hermes config # Skills hermes skills # 工具 hermes tools # Gateway hermes gateway
穩定長期使用建議：
1. 先確認模型 API 可正常生成
2. 再設定 Telegram allowlist（TELEGRAM_ALLOWED_USERS）
3. 最後才啟用 Gateway 背景服務
這樣可避免 API 額度外洩、bot 被陌生人使用，或背景化後不易排查問題。

常見問題 FAQ

Q：Hermes Agent 要如何啟動？
若安裝在 WSL HermesAgent 中，先執行 wsl -d HermesAgent，進入後執行 hermes 即可啟動互動式聊天。
Q：如何設定 Hermes 使用 Gemma 4 31B？
執行以下三條指令：
hermes config set model.provider gemini hermes config set model.default gemma-4-31b-it hermes config set model.base_url https://generativelanguage.googleapis.com/v1beta/openai
Q：Hermes 的 API key 放在哪裡？
通常放在 ~/.hermes/.env。 Google Gemini 可設定 GOOGLE_API_KEY、GEMINI_API_KEY 與 GEMINI_BASE_URL。
Q：如何綁定 Telegram？
先用 @BotFather 建立 bot 並取得 token，再用 @userinfobot 取得自己的 Telegram user ID， 接著執行 hermes setup gateway 或手動設定 TELEGRAM_BOT_TOKEN、TELEGRAM_ALLOWED_USERS、TELEGRAM_HOME_CHANNEL。
Q：為什麼 Telegram Allowed Users 很重要？
若 TELEGRAM_ALLOWED_USERS 留空，任何找到 bot 的人都有可能使用你的 Hermes 與 API 額度。建議一定要填入自己的 Telegram numeric user ID。
Q：Hermes Skills 是什麼？
Skills 是任務專長模組，可讓 Hermes 在程式碼檢查、GitHub 工作流、研究寫作、PDF、MLOps 等任務中套用更精準的流程。
